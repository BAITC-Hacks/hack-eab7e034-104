# StockPilot — помощник по пополнению склада

StockPilot помогает менеджеру закупа ТОО «Электрокомплект» планировать пополнение склада по данным продаж, остатков и товаров в пути. Сервис показывает рекомендации по SKU, причины срочности и готовит CSV-черновик для ручной проверки. Заказы автоматически не отправляются.

## Что реализовано

- Прогноз спроса с календарной сезонностью, затухающим трендом и устойчивым ограничением месячных выбросов.
- Расчёт пополнения по SKU с учётом остатков, товаров в пути, буфера 15% и MOQ.
- Срочность, группировка по поставщикам, поиск и фильтры.
- Пояснение выбранного SKU по прогнозу, запасу, MOQ и поправкам.
- Разбор продаж, снятых с регулярного спроса: поправки исходной выгрузки и автоматические ограничения месячных пиков.
- Проверка пропусков и возраста снимка остатка. Порог 14 дней — демонстрационное допущение, не срок из технического задания. Для даты `YYYY-MM` показывается диапазон возраста.
- Сравнение плана с изменённым горизонтом и множителем спроса.
- Сценарий «Что если?», загрузка периодов stockout из CSV и экспорт видимых строк в CSV со статусом «Требует ручного согласования».
- Русскоязычный помощник с локальным demo-режимом и опциональным выбором инструмента через OpenAI.

## Как работает помощник

Менеджер задаёт вопрос обычным языком. Агент выбирает подходящий инструмент для сводки плана, объяснения SKU, проверки выбросов, аудита данных, сравнения сценариев или подготовки экспорта. Расчётный код формирует факты и количества, после чего агент кратко объясняет результат. Без API-ключа локальный режим распознаёт поддерживаемые типы вопросов и работает без сети.

Примеры запросов:

- «Покажи срочные позиции IEK на 30 дней»
- «Объясни SKU 010400432»
- «Какие выбросы алгоритм исключил?»
- «Проверь качество данных, старше 14 дней»
- «Что изменилось после сценария?»
- «Подготовь CSV на ручное согласование»

AI не выполняет арифметику и не отправляет заказы. Рекомендации остаются на проверке закупщика.

## Технологии и архитектура

- **Python 3.10+**, стандартная библиотека: API на `http.server`, JSON, gzip и вызов OpenAI.
- **HTML, CSS, JavaScript** без фронтенд-фреймворка.
- **OpenAI Responses API** опционально; модель по умолчанию — `gpt-5.6-terra`, настраивается через `OPENAI_MODEL`.
- Подготовленный каталог хранится в `data/demo_catalog.json` или `data/demo_catalog.json.gz`.

```text
Браузер (frontend/)
  → app.py: HTTP API, проверка входа и загрузка каталога
      → agent.py: выбор инструмента OpenAI или локальный режим
          → replenishment.py: прогноз и проверяемые расчёты
      → JSON с планом и фактами
  → таблица, объяснение и CSV-черновик для ручного согласования
```

Основные маршруты API: `GET /api/health`, `GET /api/products`, `POST /api/recommendations`, `POST /api/agent`.

## Установка и запуск

Нужен Python 3.10 или новее. Откройте PowerShell в папке проекта:

```powershell
python --version
python app.py
```

Откройте [http://127.0.0.1:8000](http://127.0.0.1:8000). Для остановки сервера нажмите `Ctrl+C`.

Чтобы подключить OpenAI, скопируйте `.env.example` в `.env` и задайте `OPENAI_API_KEY`. Ключ не добавляйте в Git. При отсутствии ключа сайт работает в локальном demo-режиме; если API недоступен, используется локальный режим.

## Как проверить

1. Запустите сайт и отправьте агенту запрос «Покажи срочные позиции IEK на 30 дней».
2. Откройте позицию из таблицы и проверьте обоснование, остаток, товары в пути и MOQ.
3. Проверьте выбросы или свежесть данных кнопками-подсказками в панели помощника.
4. В «Что если?» задайте новый горизонт или спрос и пересчитайте план; запросите сравнение сценариев.
5. Нажмите «CSV на согласование». В выгрузке отмечено, что файл требует ручной проверки.

Проверка кода:

```powershell
python -m unittest discover -s tests -v
```

## Данные и ограничения

Каталог содержит подготовленные агрегаты из отчётов поставщиков Systeme Electric и IEK, срез датирован 22.09.2026. История продаж агрегирована по SKU и месяцу. Остатки и транзит берутся из подготовленного локального снимка; источники автоматически не обновляются. Stockout можно передать отдельным CSV с полями `sku,month,days_out`.

- В выгрузках нет обезличенного `client_id`: крупные продажи нельзя связать с конкретным покупателем. Доступна только обработка на уровне документа/SKU и месячных выбросов.
- В исходных данных нет истории stockout, цены продажи и фактических сроков поставки. Горизонт является редактируемым допущением.
- Даты части снимков IEK известны только до месяца; помощник показывает возраст диапазоном и помечает пересечение порога как неопределённость.
- Для IEK не переданы категории. Если MOQ отсутствует, используется 1 единица с пояснением.
- Нет подключения к 1С, импорта новых продаж/остатков через интерфейс, пользовательских учётных записей или отправки заказа поставщику.
- CSV — черновая выгрузка; совместимость с конкретным форматом импорта 1С не подтверждена. Точность прогноза на отдельной выборке не оценивалась.
