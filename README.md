# StockPilot — автоматизация пополнения склада

Прототип для кейса ТОО «Электрокомплект» на HackAlem AI 2026. Менеджер закупа получает проверяемый расчёт заказа по артикулам и поставщикам на основе выгрузок продаж, остатков, товаров в пути и MOQ.

## Проблема и решение

Ручной расчёт в Excel занимает время, скрывает дефицит и может принять разовую крупную продажу за регулярный спрос. StockPilot объединяет отчёты Systeme Electric и IEK, прогнозирует спрос по SKU и показывает количество, срочность, источники и краткое обоснование. Менеджер проверяет список и сам решает, утверждать ли заказ.

## Почему здесь нужен AI

Агент понимает запрос на русском языке, извлекает поставщика, срок и сценарий спроса, вызывает инструмент `calculate_replenishment_plan`, передаёт результат на проверку и объясняет вывод. OpenAI не считает закупочные количества. Все числовые расчёты и ограничения проверяет детерминированный Python-код.

При отсутствии `OPENAI_API_KEY` приложение продолжает работать в явно обозначенном локальном demo-режиме. В OpenAI отправляются текст запроса и до 10 строк результата с артикулом, наименованием, количеством и объяснением. Исходные номера счетов и данные клиентов в каталог не включаются.

## Архитектура

```text
Браузер (HTML/CSS/JS)
        │ JSON API
Python HTTP server ── агент (OpenAI Responses API, опционально)
        │                         │ function call
        ├── каталог JSON          └── calculate_replenishment_plan
        ├── прогноз спроса               │
        ├── проверка правил ◄────────────┘
        └── CSV для ручного согласования
```

## Возможности

- Сезонность по календарному месяцу и затухающий тренд на горизонте заказа.
- Учёт свободного остатка, товаров в пути, MOQ и 15% буфера к прогнозу.
- Снижение влияния крупных разовых продаж по номеру документа и устойчивое ограничение выбросов в помесячной истории.
- Загрузка stockout CSV и симуляция stockout-дней, спроса, остатка и транзита.
- Рекомендации по поставщикам с приоритетом, объяснением и CSV-экспортом.
- Строки без обязательных остатков или истории продаж показываются отдельно и не попадают в заказ.

## Технологии

Python 3.10+, стандартный `http.server`, HTML, CSS, JavaScript, JSON, `openpyxl` для обновления каталога, OpenAI Responses API для работы агента.

## Запуск

Агрегированный каталог из двух приложенных архивов включён как `data/demo_catalog.json.gz`, чтобы репозиторий оставался компактным. Приложение прочитает его автоматически; для локального расчёта достаточно Python 3.10 или новее.

```powershell
python app.py
```

Откройте `http://127.0.0.1:8000`. Сервер слушает только локальный компьютер.

Чтобы включить агента OpenAI, скопируйте `.env.example` в `.env` и задайте `OPENAI_API_KEY`. При необходимости измените `OPENAI_MODEL`. `.env` исключён из Git.

## Пересборка каталога

Установите зависимость `openpyxl` и запустите скрипт с исходными архивами:

```powershell
python -m pip install -r requirements.txt
python scripts/build_demo_data.py --systeme "путь\Systeme electric.zip" --iek "путь\IEK.zip"
```

Скрипт оставляет в JSON только месячные агрегаты по SKU, остаток, MOQ, поставки и анонимизированные признаки выбросов. Номера документов, описания накладных и строки складских транзакций отбрасываются. При наличии `data/demo_catalog.json` он имеет приоритет над сжатым snapshot.

## Stockout CSV

Заголовки: `sku,month,days_out`. Пример:

```csv
sku,month,days_out
200400085,2026-08,5
```

SKU должен присутствовать в каталоге, месяц задаётся как `YYYY-MM`, а число дней ограничивается календарём.

## Метод расчёта

1. Отрицательные месячные нетто-продажи обнуляются, чтобы возвраты не создавали отрицательную потребность. Сентябрь 2026 нормализуется из среза на 22-е число до полного месяца.
2. Счета группируются по SKU и номеру документа. Если по SKU есть минимум пять документов, крупный документ, превышающий устойчивый порог `max(5 × медиана документа, Q3 + 3 × IQR, 2 × типичный месяц)`, исключается из регулярного спроса.
3. Помесячные выбросы ограничиваются порогом `min(3 × медиана того же месяца года, 4 × медиана истории)`, если есть минимум два сравнимых месяца из прошлых лет. При меньшем числе сравнений применяется ограничение `2 × медиана истории`. Остальные месяцы сохраняют сезонный рисунок.
4. Базовый спрос — взвешенное среднее до 24 последних месяцев. Сезонный коэффициент сравнивает медиану того же месяца года с медианой положительных месяцев. Тренд сравнивает последние шесть месяцев с предыдущими шестью и затухает пропорционально горизонту.
5. Stockout компенсируется медианным дневным спросом за последние 12 полных месяцев, умноженным на дни отсутствия. Источник не содержит stockout; компенсация применяется только к загруженному CSV или выбранному what-if.
6. Цель пополнения равна прогнозу на срок поставки плюс 15% буфер. Из цели вычитаются свободный остаток и транзит. Положительный дефицит округляется вверх до кратности MOQ.
7. Срочность определяется покрытием запасом и транзитом относительно срока поставки.

## Сценарий для жюри

1. Откройте страницу с уже загруженными агрегированными отчётами.
2. Выберите «Срочное по IEK» или задайте запрос: «Какие позиции IEK заказать на 45 дней при росте спроса на 15%?».
3. Откройте строку, проверьте сезонность, тренд, остаток, транзит и MOQ.
4. В панели «Что если?» добавьте в путь 500 единиц или укажите 5 stockout-дней, затем пересчитайте.
5. Сравните изменившиеся рекомендации и выгрузите CSV на ручное согласование.

```text

Прогноз на 30 дней: 1 266 м · остаток: 211 м · в пути: 0 м · MOQ: 1 м

```

Значения примера описывают формат; приложение пересчитывает числа из `data/demo_catalog.json`.

## Ограничения

- Архивы не содержат обезличенный `client_id`, поэтому группировка повторных заказов одного клиента невозможна. Крупная продажа может быть исключена по документу и SKU.
- Записи stockout, цена продажи и срок поставки в архивах отсутствуют. Срок 30 дней — редактируемое демо-допущение. Stockout задаётся отдельным файлом или сценарием.
- IEK использует остаток на начало сентября 2026 года; Systeme Electric — свободный остаток из среза 22 сентября. Позиции без остатка или истории продаж пропускаются.
- Для SKU без MOQ в выгрузке используется 1 единица с пометкой в обосновании. Категории IEK не переданы.
- Рекомендации требуют проверки ответственным сотрудником. Отправки заказа поставщику нет.
